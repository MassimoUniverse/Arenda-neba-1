# 🔧 Исправление проблемы: фото исчезают после рестарта

## Проблема
После рестарта сервера (PM2 restart) загруженные через админ-панель фотографии исчезают.

## 🔍 Диагностика

### Шаг 1: Проверьте состояние системы

```bash
cd /opt/arenda-neba

# Получите обновления
git pull origin main

# Запустите диагностический скрипт
node check-uploads-persistence.js
```

Скрипт покажет:
- ✅ Существует ли папка `uploads`
- ✅ Сколько файлов в папке
- ✅ Какие `image_url` сохранены в базе данных
- ✅ Соответствуют ли файлы в базе данных реальным файлам
- ✅ Статус популярных карточек

### Шаг 2: Проверьте логи загрузки

```bash
# Проверьте логи на наличие ошибок загрузки
pm2 logs arenda-neba --lines 100 | grep -i "upload\|📤\|изображение\|image"
```

### Шаг 3: Проверьте базу данных

```bash
# Проверьте, что image_url сохранены в базе
sqlite3 database.db "SELECT id, title, image_url FROM services WHERE image_url LIKE '%/uploads/%' LIMIT 10;"
```

## ✅ Решение

### Вариант 1: Если файлы есть в uploads, но не в базе данных

Это означает, что файлы загрузились, но `image_url` не сохранился в базе данных.

**Исправление:**
1. Откройте админ-панель
2. Для каждой услуги, где пропало изображение:
   - Найдите файл в папке `uploads/` (последние загруженные)
   - Вручную укажите путь в поле "Основное изображение (URL)"
   - Например: `/uploads/avtovyshka-13-metrov-main-1704123456789.webp`
   - Сохраните изменения

### Вариант 2: Если файлы удаляются из uploads

Это означает, что папка `uploads` удаляется при рестарте.

**Исправление:**

1. **Проверьте .gitignore:**
```bash
cat .gitignore | grep uploads
```

Должно быть:
```
uploads/
```

2. **Проверьте deploy.sh:**
```bash
grep -A 10 "uploads" deploy.sh | head -20
```

Должна быть защита папки `uploads` от удаления.

3. **Убедитесь, что папка не удаляется:**
```bash
# Проверьте права доступа
ls -ld uploads/

# Если папки нет, создайте её
mkdir -p uploads
chmod 755 uploads

# Проверьте, что она не в git
git status uploads/
# Должно показать "nothing to commit" или "untracked files"
```

### Вариант 3: Если база данных не сохраняет image_url

Это означает, что при сохранении услуги `image_url` не записывается в базу.

**Исправление:**

1. **Проверьте логи при сохранении:**
```bash
pm2 logs arenda-neba --lines 200 | grep -i "image_url\|обновление услуги"
```

Должны быть строки:
```
🔄 Обновление услуги в базе данных:
   image_url (до обработки): /uploads/...
   image_url (после обработки): /uploads/...
✅ image_url будет сохранен: /uploads/...
```

2. **Если image_url пустой:**
   - Убедитесь, что при загрузке изображения поле "Основное изображение (URL)" заполняется
   - Проверьте консоль браузера (F12) на наличие ошибок при загрузке

## 🛡️ Профилактика

### 1. Регулярные бэкапы

```bash
# Создайте бэкап uploads
tar -czf uploads_backup_$(date +%Y%m%d_%H%M%S).tar.gz uploads/

# Создайте бэкап базы данных
cp database.db database_backup_$(date +%Y%m%d_%H%M%S).db
```

### 2. Проверка перед рестартом

```bash
# Перед рестартом проверьте количество файлов
find uploads -type f | wc -l

# После рестарта проверьте снова
find uploads -type f | wc -l

# Если количество уменьшилось - проблема с защитой uploads
```

### 3. Автоматическая проверка

Добавьте в cron проверку каждые 5 минут:

```bash
# Добавьте в crontab
crontab -e

# Добавьте строку:
*/5 * * * * cd /opt/arenda-neba && node check-uploads-persistence.js >> /var/log/uploads-check.log 2>&1
```

## 📋 Чеклист после рестарта

После каждого рестарта проверьте:

- [ ] Папка `uploads` существует: `ls -ld uploads/`
- [ ] Файлы в папке: `ls -lh uploads/ | head -10`
- [ ] База данных содержит image_url: `sqlite3 database.db "SELECT COUNT(*) FROM services WHERE image_url LIKE '%/uploads/%';"`
- [ ] Популярные карточки отображаются: Откройте главную страницу
- [ ] Логи без ошибок: `pm2 logs arenda-neba --lines 50`

## 🆘 Если ничего не помогло

Выполните полное восстановление:

```bash
cd /opt/arenda-neba

# 1. Остановите приложение
pm2 stop arenda-neba

# 2. Восстановите uploads из бэкапа (если есть)
# Найдите последний бэкап
ls -lt uploads_backup_*.tar.gz | head -1

# Распакуйте
tar -xzf uploads_backup_YYYYMMDD_HHMMSS.tar.gz

# 3. Восстановите базу данных из бэкапа (если есть)
cp database_backup_YYYYMMDD_HHMMSS.db database.db

# 4. Запустите приложение
pm2 restart arenda-neba

# 5. Проверьте
node check-uploads-persistence.js
```

## 💡 Важные замечания

1. **НЕ добавляйте `uploads/` в git** - она должна быть в `.gitignore`
2. **Всегда используйте `deploy.sh` для деплоя** - он защищает uploads
3. **Регулярно создавайте бэкапы** - используйте `backup-full.sh`
4. **Проверяйте логи** после каждой загрузки изображения
