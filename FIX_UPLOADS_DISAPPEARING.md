# 🔧 Исправление проблемы исчезновения загруженных файлов после деплоя

## Проблема
После деплоя фотографии, загруженные через админ панель, исчезают.

## ✅ Решение

### 1. Автоматическое создание папки uploads

Теперь папка `uploads` создается автоматически при запуске сервера. При старте сервера вы увидите в логах:

```
✅ Папка uploads существует
✅ Папка uploads доступна для записи
```

### 2. Защита от удаления при деплое

Скрипт `deploy.sh` теперь:
- **Создает резервную копию** папки `uploads` перед деплоем
- **Восстанавливает файлы** из резервной копии, если они были удалены
- **Проверяет существование** папки `uploads` после деплоя
- **Устанавливает правильные права** доступа (755)

### 3. Проверка на сервере

После деплоя проверьте:

```bash
cd /opt/arenda-neba

# Проверьте, что папка существует
ls -la uploads/

# Проверьте права доступа
ls -ld uploads
# Должно быть: drwxr-xr-x

# Если прав нет, установите их:
chmod 755 uploads
```

### 4. Восстановление файлов из резервной копии

Если файлы исчезли, найдите резервную копию:

```bash
cd /opt/arenda-neba

# Найдите резервные копии
ls -la uploads_backup_*

# Восстановите из последней резервной копии
cp -r uploads_backup_YYYYMMDD_HHMMSS/* uploads/
```

### 5. Проверка базы данных

Убедитесь, что пути к файлам сохранены в базе данных:

```bash
cd /opt/arenda-neba

# Проверьте image_url в базе данных
sqlite3 database.db "SELECT id, title, image_url FROM services WHERE image_url IS NOT NULL;"
```

### 6. Проверка логов сервера

Проверьте логи при загрузке файла:

```bash
pm2 logs arenda-neba --lines 50
```

Должны увидеть:
```
✅ Папка uploads существует
✅ Папка uploads доступна для записи
📤 Загружен файл: filename.webp
✅ Изображение успешно конвертировано
```

## Если проблема осталась

### Вариант 1: Ручное восстановление из бекапа

Если у вас есть полный бекап проекта:

```bash
cd /opt/arenda-neba

# Восстановите uploads из бекапа
cp -r /path/to/backup/uploads/* uploads/
chmod 755 uploads
```

### Вариант 2: Проверка синхронизации

Убедитесь, что папка `uploads` не в `.gitignore` (она не должна быть там):

```bash
cd /opt/arenda-neba
cat .gitignore | grep uploads
# Не должно быть вывода (uploads не должна быть в .gitignore)
```

### Вариант 3: Проверка прав пользователя

Убедитесь, что пользователь, под которым запущен PM2, имеет права на запись:

```bash
# Проверьте, под каким пользователем запущен PM2
pm2 info arenda-neba | grep username

# Установите правильного владельца
sudo chown -R $USER:$USER uploads/
chmod 755 uploads
```

## Профилактика

1. **Регулярные бекапы**: Используйте скрипт `backup-full.sh` для регулярных бекапов
2. **Мониторинг**: Проверяйте логи после каждого деплоя
3. **Проверка файлов**: После деплоя проверяйте, что файлы на месте:

```bash
cd /opt/arenda-neba
ls -lh uploads/ | head -20
```

## После исправления

1. Перезапустите сервер:
   ```bash
   pm2 restart arenda-neba
   ```

2. Проверьте логи:
   ```bash
   pm2 logs arenda-neba --lines 20
   ```

3. Загрузите тестовое изображение через админ панель и убедитесь, что оно сохраняется
