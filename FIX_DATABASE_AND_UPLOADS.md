# 🔧 Исправление проблемы с пропаданием базы данных и изображений

## Проблема
После `git pull` или деплоя пропадали:
- База данных `database.db`
- Загруженные изображения из папки `uploads/`

## ✅ Решение

### Что было исправлено:

1. **Обновлен `.gitignore`** - база данных и uploads теперь точно не попадают в git
2. **Улучшен `deploy.sh`** - добавлена полная защита базы данных и uploads от удаления

### Как работает защита:

1. **Перед `git pull/reset`:**
   - Создается резервная копия базы данных
   - Создается резервная копия папки uploads
   - База данных временно переименовывается (защита от git)
   - Папка uploads временно переименовывается (защита от git)

2. **После `git pull/reset`:**
   - База данных восстанавливается из временного файла
   - Если временный файл не найден - восстанавливается из резервной копии
   - Папка uploads восстанавливается из временной папки
   - Если временная папка не найдена - восстанавливается из резервной копии

3. **Автоматическая очистка:**
   - Старые резервные копии (старше 7 дней) удаляются автоматически
   - Временные файлы (старше 1 дня) удаляются автоматически

## 📋 Инструкция по использованию

### На сервере выполните:

```bash
cd /opt/arenda-neba

# 1. Получите обновленный скрипт деплоя
git pull origin main

# 2. Убедитесь, что база данных и uploads в .gitignore
cat .gitignore | grep -E "database|uploads"

# Должны увидеть:
# database.db
# uploads/

# 3. Если база данных или uploads случайно попали в git, удалите их из индекса:
git rm --cached database.db 2>/dev/null || true
git rm --cached -r uploads/ 2>/dev/null || true

# 4. Запустите деплой (скрипт автоматически защитит базу и uploads)
chmod +x deploy.sh
./deploy.sh
```

## ⚠️ Если проблема осталась

### Вариант 1: Восстановление из резервной копии

```bash
cd /opt/arenda-neba

# Найдите последнюю резервную копию базы данных
ls -lt database_backup_*.db | head -1

# Восстановите базу данных
cp database_backup_YYYYMMDD_HHMMSS.db database.db

# Найдите последнюю резервную копию uploads
ls -ltd uploads_backup_* | head -1

# Восстановите uploads
rm -rf uploads
cp -r uploads_backup_YYYYMMDD_HHMMSS uploads
chmod 755 uploads

# Перезапустите приложение
pm2 restart arenda-neba
```

### Вариант 2: Ручное восстановление

Если резервных копий нет, но у вас есть бэкап:

```bash
cd /opt/arenda-neba

# Остановите приложение
pm2 stop arenda-neba

# Восстановите базу данных из вашего бэкапа
cp /path/to/your/backup/database.db ./database.db

# Восстановите uploads из вашего бэкапа
rm -rf uploads
cp -r /path/to/your/backup/uploads ./uploads
chmod 755 uploads

# Запустите приложение
pm2 start arenda-neba
```

## 🎯 Про конвертацию в WebP

Конвертация в WebP **НЕ** является причиной пропадания файлов. Она происходит **после** сохранения оригинального файла:

1. Загружается оригинальный файл → сохраняется в `uploads/`
2. Создается WebP версия → сохраняется рядом с оригиналом
3. Оба файла остаются в `uploads/`

Проблема была в том, что при `git pull` папка `uploads/` удалялась командой `git clean -fd`, потому что она не была защищена.

- ✅ Папка uploads защищена от удаления
- ✅ Автоматическое создание резервных копий
- ✅ Автоматическое восстановление при необходимости
